=====================================================
1. INTRODUCTION
=====================================================

PC Build Store is a desktop application designed to help users configure,
compare, and purchase custom PC builds. The application provides a
comprehensive catalog of 78+ components across 6 categories (CPU, GPU,
RAM, Storage, PSU, Motherboard) with real pricing data from the Pakistani
market.

The system allows users to:
- Browse and search PC components by category
- Build custom PCs with real-time compatibility filtering
- Upgrade existing builds with smart compatibility checks
- Purchase builds and receive printable/saveable receipts
- Get AI-powered build suggestions through an integrated chat bot

The application is built using Java 17 with Swing GUI and MariaDB for
data persistence, following object-oriented design principles throughout.

=====================================================
2. PROBLEM STATEMENT
=====================================================

Building a custom PC is a complex task that requires knowledge of
hardware compatibility, pricing, and performance metrics. Users often
struggle with:

- Identifying compatible components across different categories
- Comparing prices from multiple vendors
- Understanding technical specifications (socket types, DDR generations,
  power requirements)
- Getting expert advice on optimal configurations

Our solution addresses these challenges by providing an intelligent
PC configurator with automated compatibility checks, real-time pricing,
and AI-powered recommendations.

4. SYSTEM ARCHITECTURE
=====================================================

The application follows a layered MVC (Model-View-Controller) architecture:

PRESENTATION LAYER (GUI)
-------------------------
- DashboardGUI: Main navigation hub with hero section, stats, and chat
- BuildCatalogGUI: 6-slot PC builder with category tabs and product grid
- BuildUpgradesGUI: Upgrade system with compatibility checks
- BillingGUI: Purchase flow with receipt generation
- ReportGUI: Revenue and performance analytics charts
- AddPartDialog: Modal form for adding components
- ChatSettingsDialog: AI configuration dialog

BUSINESS LOGIC LAYER (DAO)
---------------------------
- BillDAO: Purchase operations and receipt generation
- BuildDAO: Build CRUD operations and part management
- CategoryDAO: Category retrieval and caching
- PartDAO: Component queries, search, and filtering
- GPUOptionDAO: GPU-specific upgrade options
- ReportDAO: Analytics aggregation queries

DATA ACCESS LAYER (JDBC)
-------------------------
- DBConnection: MariaDB connection pool management
- JDBC drivers for MySQL/MariaDB communication

MODEL LAYER (POJOs)
--------------------
- Bill: Purchase record with build reference and pricing
- Build: PC configuration with total price and score
- BuildPart: Junction table for build-component relationships
- Category: Component category (CPU, GPU, etc.)
- Part: Hardware component with full specifications
- GPUOption: GPU-specific upgrade option

UTILITY LAYER
--------------
- ImageCache: 3-tier caching (memory, disk, HTTP) with LRU eviction
- ChatService: SSE streaming for OpenAI-compatible APIs
- ChatConfig: Persistent settings management
- Components: Theme-consistent UI factories

DATA FLOW:
User Interface -> DAO Layer -> JDBC -> MariaDB -> DAO -> UI Update

6. INTEGRATION STRATEGY
=====================================================

The integration was performed in phases:

Phase 1 - Database Setup:
- Created MariaDB schema with 6 tables
- Populated 78+ components with real pricing data
- Established JDBC connection pool

Phase 2 - Module Development:
- Each team member developed their assigned module independently
- Used consistent theme (Theme.java) for uniform appearance
- Shared DAO layer for database operations

Phase 3 - Cross-Module Integration:
- Dashboard links to all modules via navigation buttons
- Build Catalog passes selected builds to Upgrades module
- Billing receives completed builds for purchase processing
- Reports aggregate data from all modules

Phase 4 - Feature Completion:
- Added AI chat integration with streaming responses
- Implemented image caching for product photos
- Added receipt print and save functionality
- Created add part dialog for manual component entry

7.3 Build Upgrades Module (Aitzaz)
-----------------------------------
The upgrade system allows:
- Loading existing builds for modification
- 6-slot upgrade interface with current parts displayed
- Compatibility checking (socket, DDR, wattage)
- Apply upgrades button to save changes

Key Implementation:
- Socket compatibility matrix for CPU-Motherboard matching
- DDR generation validation for CPU-RAM compatibility
- Wattage calculation for PSU headroom checking
- Build part replacement with score recalculation

7.4 Billing Module (Ahmad Mushtaq)
-----------------------------------
The billing system provides:
- Build summary display with all selected parts
- Purchase processing with database storage
- Receipt view with formatted HTML output
- Print receipt via java.awt.print.PrinterJob
- Save receipt as HTML file via JFileChooser

Key Implementation:
- Printable interface for receipt formatting
- HTML receipt generation with table layout
- JFileChooser with null parent to avoid modal blocking

7.5 Reports Module (Abdulhanan)
-------------------------------
The reports module generates:

The chat system provides:

price           | INT          | NOT NULL

ddr_generation  | INT          | NULL

clock_speed     | DOUBLE       | NULL
vram            | INT          | NULL
memory_speed    | INT          | NULL
capacity        | INT          | NULL
read_speed      | INT          | NULL
wattage         | INT          | NULL
efficiency      | VARCHAR(10)  | NULL
image_path      | VARCHAR(500) | NULL

8.3 Table: builds
-----------------
Column       | Type         | Constraint
-------------|--------------|------------------
build_id     | INT          | PK AUTO_INCREMENT
name         | VARCHAR(100) | NOT NULL
total_price  | INT          | DEFAULT 0
total_score  | INT          | DEFAULT 0

8.4 Table: build_parts
----------------------
Column      | Type | Constraint
------------|------|------------------
build_id    | INT  | FK -> builds, PK
category_id | INT  | FK -> categories, PK
part_id     | INT  | FK -> parts
price_at_add| INT  | NOT NULL

8.5 Table: bills
----------------
Column       | Type      | Constraint
-------------|-----------|------------------
bill_id      | INT       | PK AUTO_INCREMENT
build_id     | INT       | FK -> builds
final_price  | INT       | NOT NULL
final_score  | INT       | NOT NULL
purchase_date| TIMESTAMP | DEFAULT CURRENT_TIMESTAMP

11. CONCLUSION
=====================================================

The PC Build Store project demonstrates effective application of
object-oriented programming principles including:

- Encapsulation: Model classes with private fields and public getters
- Inheritance: JPanel anonymous inner classes for custom components
- Polymorphism: DAO pattern for interchangeable data access
- Abstraction: Separation of concerns across layers
- Composition: GUI panels composed of specialized sub-components

The modular architecture allowed parallel development by team members
while maintaining code consistency through shared theme and DAO layers.

Key technical achievements:
- Streaming AI integration with KoboldCPP
- 3-tier image caching system

The project provides a solid foundation for future enhancements such as
price comparison across multiple vendors, user accounts with build
